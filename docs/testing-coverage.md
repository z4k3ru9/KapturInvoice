# KapturInvoice — Test Coverage Design

What "tested" means here, and a domain-by-domain map of what actually is,
so a gap is a documented decision rather than an unknown. Almost every
test is a Feature test under `tests/Feature/` (PHPUnit + `RefreshDatabase`
+ Livewire's `Livewire::test()`/`assertOk()` HTTP checks); a handful of
pure-logic classes with no database/HTTP involvement (`DashboardPeriod`,
`PortfolioContent`) get a plain `tests/Unit/` test instead — there's no
browser/E2E suite (see **What's out of scope**, below).

Run the whole suite with `php artisan test` (see `CLAUDE.md` for the
current count) and `vendor/bin/pint --test` before every push.

## Approach

- **The admin is a hand-built TallStackUI/Livewire admin**, not Filament
  (`app/Filament` was removed entirely — every resource now has an
  `App\Livewire\TallStack*` counterpart routed at
  `/tall/{company:slug}/...`; see `README.md`'s Architecture section).
  There is no single generic "does every page render?" sweep test the way
  Filament's `Resource::getPages()` once allowed; instead each
  TallStack component gets its own feature test under
  `tests/Feature/TallStack/` (or, where a component's behavior is really
  about a domain workflow rather than the page shell, alongside that
  domain's test file — e.g. `tests/Feature/Sales/`,
  `tests/Feature/Receivables/`). The pattern is `Livewire::test($Component::class,
  ['company' => $company, ...])->assertOk()` / `->call('method', ...)`
  after `actingAs()` a user attached to the company via the `company_user`
  pivot (`$company->users()->attach($user, ['role' => 'owner'])`) — no
  `Filament::setTenant()` equivalent is needed since these components
  resolve their tenant from the route-bound `$company` prop and re-check
  ownership explicitly in `mount()` (see any `TallStack*` component's own
  docblock). `tests/Feature/LoginTest.php` covers the plain `/login` page
  itself (`App\Livewire\Login`) and its post-login redirect to the user's
  first active company's dashboard.
- **Domain-specific behavior** gets its own focused test file per area
  (below), covering business logic a generic page-render check can't:
  tenant isolation, computed totals, state transitions, service classes.
  Many of these (e.g. `InvoiceIssuanceTest`, `PaymentWorkflowTest`,
  `VendorBillWorkflowTest`) test the underlying `App\Actions\*` classes
  directly rather than through a Livewire component, since the actions
  themselves — not any particular UI wiring — own the financial rules.
- **External calls are faked, never live**: `Mail::fake()` for
  `BillingMailer`, `Http::fake()` for `LocalApiPaymentGatewayDriver` —
  every driver/mailer call is a real call into Laravel's HTTP/Mail
  clients, so faking them exercises the real request-building/response-
  mapping code, not a mocked-out shortcut.
