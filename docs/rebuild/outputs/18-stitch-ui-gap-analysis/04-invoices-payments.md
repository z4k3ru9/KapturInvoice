
# Gap analysis — Stitch billing/payments screens vs. current implementation

**Scope:** read-only. Filament v5.7.8 (`composer.lock`). Governing rules: `docs/rebuild/DESIGN.md` §7–§9, §16; `docs/rebuild/specs/04-billing-and-receivables/Specs.md`; `docs/rebuild/specs/FINALIZED-DECISIONS.md` §3, §4, §8, §9; `memory.md` "Financial rules".

## 0. Cross-cutting findings (apply to all four screens)

**Facts verified in code**
- `app/Filament/Resources/Invoices/InvoiceResource.php` has **no `getEloquentQuery()` override** → the "Invoices" list currently shows `type=quote` rows and `is_recurring=true` templates too (the Quotes resource scopes `->where('type', Quote)`, RecurringInvoices scopes `->where('is_recurring', true)`, Invoices scopes nothing). The `type` badge column + `type` filter in `InvoicesTable.php` exist only because of this leak.
- `InvoiceStatus::Overdue` (`app/Enums/InvoiceStatus.php`) is **never written by app code** — only read by `app/Console/Commands/SendInvoiceReminders.php:68`. It is a stored status only on imported rows. Overdue must be **derived** (`balance > 0 && due_date < today && status ∉ {Paid, Cancelled, Draft}`).
- `invoices` has no `sales_order_id`; `Payment` has a single `invoice_id` (no allocation rows); no receipt, tax-recap, snapshot, or `pricing_mode` columns on invoices (`pricing_mode` exists only on `quotations`). `CompanyTaxSetting` (`company_tax_settings.tax_enabled/default_tax_mode/standard_tax_rate/dpp_factor_*`) exists but is not read by any billing UI.
- `AuditEvent` + `AuditLogger` exist (append-only, `entity_type/entity_id`), but no invoice/payment code writes to them (only `ApproveJobVariation`, `PeriodLockService`, `CompanyMembershipService`).
- Nav: Stitch puts *Customer Invoices* and *Payments & Receipts* under **Sales** (matches DESIGN §2 shell); current `InvoiceResource`/`PaymentResource`/`CreditResource` use `$navigationGroup = 'Billing'`; `Quotation`/`SalesOrder` already use `'Sales'`.
- No shared Rupiah formatter exists; tables use bare `->numeric()`, widgets use `number_format(...,2)`. Products infolist uses `->money()`.

**[STRIP] tells present in all four Stitch files (DESIGN §16 / FD §9)** — do not carry into implementation:
- "DJP e-Faktur Sync: Active", "Sync DJP NSFP", "Approved DJP", "Valid on DJP", "BSrE National Cryptographic Signature", "DJP Tax Cloud Synchronized · SHA256…", "Generate e-Faktur CSV Dump", "Fiscal Lock: Q3-2026 Validated", "PMK-18/PMK.03/2021 … verified" footer, "Cross-Entity Guard Dog", "Allocation Policy §7 Compliant" — FD §9: "The software does not file, sign, or certify tax documents"; no certification/attestation claims. The external tax-system serial belongs only as a **manual free-text field on the Phase 04 tax recap** (FD §3 "external tax-system reference/serial, manual-entry status").
- **PPN 11%** everywhere → approved rule is **12% with 11/12 DPP Nilai Lain** (FD §3, memory.md). Stitch DPP math (`175.000.000 / 1.11`) is the wrong formula.
- **PPh 23 (2% WAPU withholding)**, "WAPU BUMN Tax Notice", "Net Receivable (DPP)" lines — not in Phase 04 spec; "Other tax brackets are deferred" (FD §3). Strip from invoice totals.
- "Escrow Virtual Account", "Client Escrow Credit", "Review Credit Ledger", "Will post to escrow balance", `refunded_amount`/"Refund" — gateway/refund/write-off deferred (CLAUDE.md guards, FD §4).
- "Non-PKP" KPI copy about "PPh Final PP 55 / 0.5% UMKM Ledger", "Buku Rekap Omzet", "Unduh Surat Pernyataan Non-PKP", legal-basis footer — Karunia is simply `tax_enabled=false`; no regulatory-reporting features (FD §9).
- "System Online v2.4", "Industry Benchmark: Top 10%", "Weighted run-rate", WhatsApp follow-up badge, "Automated dispatch … secure webhook to EDI node" activity copy — decorative/fabricated.
- Middle-dot-joined meta strings, all-caps eyebrow labels — DESIGN §16 explicit tells.
